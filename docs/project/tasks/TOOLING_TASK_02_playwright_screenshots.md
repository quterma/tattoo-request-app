## Goal

Give an implementation session the ability to **see** the rendered public site at named viewport
widths, so visual acceptance criteria stop being deferred as unexecutable manual checks. Today no
AI session in this repository can render a page: there is no Playwright/Puppeteer/Cypress in
`package.json`, which is why the mobile-viewport completion obligations of Items 5, 6 and 16 all
closed as gaps rather than as evidence.

## Scope

1. Add **`playwright`** (core package, not `@playwright/test`) as a **devDependency**. The core
   package is deliberate: this task needs a browser driver for screenshots, not a second test
   runner alongside `vitest`.
2. Add `scripts/screenshots.mjs` — a standalone node script following the conventions of the two
   existing scripts (`project-status.mjs`, `update-structure.mjs`). It:
   - takes a base URL (default `http://localhost:3000`) and an optional list of routes;
   - defaults to the full public route set: `/en`, `/en/process`, `/en/request`, `/en/location`,
     `/en/preparation`, `/en/aftercare`;
   - captures each route at **four widths: 320, 375, 768, 1280** (320 is the layout's declared
     `min-w-[320px]` floor; 375 is the common phone width; 768/1280 cross the `sm:`/`lg:`
     breakpoints the pages actually use);
   - writes full-page PNGs to `screenshots/<route-slug>-<width>.png`;
   - exits non-zero with a readable message if the server is not reachable, rather than hanging.
3. Add a `pnpm shot` script to `package.json` invoking it.
4. Add `screenshots/` to `.gitignore` — captures are working artifacts and must never be committed.
5. Document the one-time browser install (`pnpm exec playwright install chromium`) in the script's
   own failure message, so a session that hits the missing-browser error is told how to fix it
   without reading docs.
