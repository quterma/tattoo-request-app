## Review 1

1. **Should-fix — missing-browser detection misclassifies unrelated Chromium launch failures.**
   `scripts/screenshots.mjs:85-89` accepts `browserType.launch` as sufficient evidence that the
   executable is absent. Playwright prefixes launch failures with the API call name, so failures
   such as a sandbox/permission problem, a crashed browser process, or an invalid host environment
   can match this branch and be reported as “Chromium browser is not installed.” Match the
   missing-executable wording (and, if needed, Playwright's install-command wording) narrowly;
   otherwise rethrow the original launch error.

2. **Should-fix — reachability detection can swallow a failure after the server was reached.**
   `scripts/screenshots.mjs:76-82` treats every message matching `Timeout.*exceeded` as a connection
   error, while the catch at `scripts/screenshots.mjs:113-124` covers the entire capture:
   navigation, scrolling, evaluation, screenshot writing, and context cleanup. A screenshot or
   page-operation timeout would therefore produce the false instruction to start an already-running
   server and hide the actionable Playwright error. Restrict the readable reachability handling to
   the `page.goto` operation and/or to navigation connection-refusal error shapes; do not classify a
   generic timeout from the rest of the capture as server unreachability.

3. **Should-fix — supported custom routes can produce invalid Windows filenames.**
   The task explicitly permits an optional route list, but `routeSlug` at
   `scripts/screenshots.mjs:26-29` removes only leading and internal `/`. A valid route such as
   `/en/process?mode=compact` leaves `?` in the PNG path, and an absolute custom URL leaves `:`;
   both are forbidden in Windows filenames. Backslashes and other reserved characters are also
   retained. Derive the slug from the resolved URL pathname and sanitize it to a portable filename
   (with an explicit fallback for `/`), so the advertised custom-route path works on the project's
   current Windows environment.

## Response 1

All three findings accepted and fixed in `scripts/screenshots.mjs`:

1. **Accepted (missing-browser detection).** Narrowed `isMissingBrowserError` to match only
   `Executable doesn't exist` (Playwright's actual missing-executable wording), dropping the
   over-broad `browserType\.launch` alternative that matched any launch failure. A sandbox/
   permission/crash failure now rethrows as-is instead of being misreported as "not installed".
2. **Accepted (reachability detection scope).** Introduced a small `UnreachableServerError` wrapper
   thrown only around the `page.goto` call inside `captureRoute` (checked against
   `isConnectionError`, which no longer includes the generic `Timeout.*exceeded` pattern — only
   `ERR_CONNECTION_REFUSED` / `ECONNREFUSED` / `net::ERR_*`). The outer per-route catch in
   `runScreenshots` now matches on `error instanceof UnreachableServerError` specifically, so a
   timeout during scrolling, evaluation, or screenshot-writing rethrows as its real error instead of
   being misreported as "is the server running?".
3. **Accepted (Windows-unsafe filenames from custom routes).** `routeSlug` now takes the resolved
   `URL` object (not the raw route string), derives the slug from `url.pathname` only (query strings
   and any scheme/host from an absolute custom URL are dropped by construction), and sanitizes
   remaining characters to `[A-Za-z0-9_-]` with a `root` fallback for `/`. Manually verified:
   `/en/process?mode=compact` now writes `en-process-<width>.png` (no `?`, no crash) instead of
   leaving the query string in the path.

Re-verification after the fix: `pnpm lint` and `pnpm typecheck` re-run clean (same pre-existing
warning, 0 errors). Full capture re-run against `pnpm build && pnpm start` reproduced the same 24
files with identical slugs/dimensions/no-overflow result as the original Handoff run. Re-ran the
